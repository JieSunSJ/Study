## 单元测试
单元测试:就是针对最小的功能单元(方法),编写测试代码对其正确性进行测试。
测试:是一种用来促进鉴定软件的正确性、完整性、安全性和质量的过程。
阶段划分:单元测试、集成测试、系统测试、验收测试。
#### main方法测试
```
1. 测试代码与源代码未分开,难维护
2. 一个方法测试失败,影响后面方法
3. 无法自动化测试,得到测试报告
```
#### JUnit
最流行的Java测试框架之一,提供了一些功能,方便程序进行单元测试(第三方公司提供)
```
1. 测试代码与源代码分开,便于维护
2. 可根据需要进行自动化测试
3. 可自动分析测试结果,产出测试报告
```
### 单元测试
测试方法：白盒测试
```
介绍:对软件的基本组成单位进行测试,最小测试单位。
目的:检验软件基本组成单位的正确性。
测试人员:开发人员
```
### 集成测试
测试方法：灰盒测试
```
介绍:将已分别通过测试的单元,按设计要求组合成系统或子系统,再进行的测试。
目的:检查单元之间的协作是否正确。
测试人员:开发人员
```
### 系统测试
测试方法：黑盒测试
```
介绍:对已经集成好的软件系统进行彻底的测试。
目的:验证软件系统的正确性、性能是否满足指定的要求。
测试人员:测试人员
```
### 验收测试
测试方法：黑盒测试
```
介绍:交付测试,是针对用户需求、业务流程进行的正式的测试。
目的:验证软件系统是否满足验收标准。
测试人员:客户/需求方
```
测试方法:白盒测试、黑盒测试及灰盒测试。
#### 白盒测试
清楚软件内部结构、代码逻辑。
用于验证代码、逻辑正确性。
#### 黑盒测试
不清楚软件内部结构、代码逻辑。
用于验证软件的功能、兼容性等方面。
#### 灰盒测试
结合了白盒测试和黑盒测试的特点,既关注软件的内部结构又考虑外部表现(功能)。

## 快速入门
###  使用JUnit,对N-Service中业务方法进行单元测试。
在pom.xml中,引入JUnit的依赖。
```
<dependency>
<groupId>org.junit.jupiter</groupId>
<artifactId>junit-jupiter</artifactId>
<version>5.9.1</version>
</dependency>
```
在test/java目录下,创建测试类,并编写对应的测试方法,并在方法上声明@Test注解。
	JUnit单元测试类名命名规范为:XxxxxTest【规范】。JUnit单元测试的方法,必须声明为 public void【规定】。
```
//    测试类  
public class UserServiceTest {  
    @Test  
    public void testAddUser() {  
        UserService userService = new UserService();  
        userService.addUser("张三");  
    }  
}
```
### 单元测试运行不报错(绿色),就代表代码没问题,测试通过?
不是
为了准确的测试，要使用断言
## 断言
JUnit提供了一些辅助方法,用来帮我们确定被测试的方法是否按照预期的效果正常工作,这种方式称为断言。
![[Pasted image 20260812135048.png]]
	上述方法形参中的最后一个参数 msg,表示错误提示信息,可以不指定(有对应的重载方法)。
```
@Test  
public void testGetUserById() {  
    UserService userService = new UserService();  
    String user = userService.getUserById(2);  
    //断言  
    Assertions.assertEquals("用户1", user, "获取用户失败");  
}
```
结果
```
org.opentest4j.AssertionFailedError: 获取用户失败 ==> 
预期:用户1
实际:用户2
```
### 关于 assertThrows
```
它是 JUnit Jupiter（org.junit.jupiter.api.Assertions）中的静态方法，用于断言某个代码块执行时抛出指定类型的异常。
第一个参数是期望的异常类型（Class<T>），第二个参数是一个 Executable（函数式接口），通常用 Lambda 表达式包裹待测代码。
如果 Lambda 内部没有抛出期望的异常，测试会失败；如果抛出的是其他异常，也会失败。
```
```
import org.junit.jupiter.api.Test;
import static org.junit.jupiter.api.Assertions.assertThrows;

class UserServiceTest {
    private UserService userService = new UserService();

    @Test
    void getGenderShouldThrowNPEWhenIdCardIsNull() {
        assertThrows(NullPointerException.class, () -> {
            userService.getGender(null);
        });
    }
}
```
```
为什么必须用 .class 而不是 new？
 用 new NullPointerException() 是创建了一个具体的异常实例（对象），它带有栈轨迹等信息。assertThrows 无法用两个不同的对象实例（你传的实例 vs 代码抛出的实例）做 == 比较来判断类型，这既不准确也不安全。
 
 用 .class 得到的是类型信息，assertThrows 用它来判断“类型是否匹配”（`instanceof` 的关系），这才是我们真正想测试的东西。
```
在JUnit单元测试中,为什么要使用断言?
单元测试方法运行不报错,不代表业务方法没问题。
通过断言可以检测方法运行结果是否和预期一致,从而判断业务方法的正确性
Assertions.assertXxxx( ... )
## 常见注解

```
package cn.hytc;  
  
import org.junit.jupiter.api.*;  
  
//    测试类  
public class UserServiceTest {  
    @BeforeAll  
    public static void setup() {  
        System.out.println("测试开始");  
    }  
    @AfterAll  
    public static void teardown() {  
        System.out.println("测试结束");  
    }  
    @BeforeEach  
    public void beforeEach() {  
        System.out.println("每个测试方法前执行");  
    }  
    @AfterEach  
    public void afterEach() {  
        System.out.println("每个测试方法后执行");  
    }  
    @Test  
    public void testAddUser() {  
        UserService userService = new UserService();  
        userService.addUser("张三");  
    }  
    //断言  
    @Test  
    public void testGetUserById() {  
        UserService userService = new UserService();  
        String user = userService.getUserById(1);  
        //断言  
        Assertions.assertEquals("用户1", user, "获取用户失败");  
    }  
}
```
结果：
```
测试开始
每个测试方法前执行
添加用户: 张三
每个测试方法后执行
每个测试方法前执行
每个测试方法后执行
测试结束
```

## Maven依赖范围
在maven项目中,test目录存放单元测试的代码,是否可以在
main目录中编写单元测试呢?
### 依赖范围
```
依赖的jar包,默认情况下,可以在任何地方使用。可以通过 <scope> ...< /scope>设置其作用范围。
```
作用范围:
```
主程序范围有效。(main文件夹范围内)
测试程序范围有效。(test文件夹范围内)
是否参与打包运行。(package指令范围内)
```
scope
```
<dependencies>
        <dependency>
            <groupId>org.junit.jupiter</groupId>
            <artifactId>junit-jupiter</artifactId>
            <version>5.10.2</version>
            <scope>test</scope>
        </dependency>
    </dependencies>
```
